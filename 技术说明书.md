## 1. 项目概述

Service Deck 是一个**本地开发服务管理桌面应用**，用于集中管理和监控开发者机器上运行的各种本地服务（如前端开发服务器、后端 API 服务、数据库等）。

### 核心功能

- **服务管理**：添加、编辑、删除本地服务，配置启动命令和工作目录
- **项目管理**：将多个服务组合成项目，支持一键启动/停止整个项目的所有服务
- **进程管理**：启动、停止、重启服务进程，实时监控运行状态
- **日志查看**：实时查看服务的控制台输出或日志文件内容
- **批量操作**：同时对多个服务执行启动、停止、重启操作
- **拖拽排序**：通过拖拽调整服务和项目的显示顺序
- **收藏功能**：收藏常用的服务和项目，置顶显示
- **备份恢复**：导出/导入配置文件，支持数据迁移
- **命令终端**：为 npm 和 Maven 类型服务提供内置命令执行终端
- **系统托盘**：支持最小化到系统托盘，后台运行

### 应用形态

这是一个**桌面应用程序**（非浏览器 Web 应用），使用 Tauri v2 框架构建，拥有原生窗口和系统托盘功能。前端使用 React + TypeScript 构建用户界面，后端使用 Rust 处理进程管理和数据持久化。

## 2. 技术栈详解

### 2.1 Tauri v2

**是什么**：Tauri 是一个用于构建跨平台桌面应用的框架，类似于 Electron，但使用系统自带的 WebView 而非捆绑 Chromium，因此打包体积更小、内存占用更低。

**为什么用**：
- 比 Electron 更轻量（打包后约几 MB，而非几十 MB）
- 后端使用 Rust，性能优秀且内存安全
- 提供原生 API 访问（文件系统、进程管理、系统托盘等）
- 跨平台支持（Windows、macOS、Linux）

**本项目中的使用**：
- `@tauri-apps/api`：前端调用后端功能的 JavaScript API
- `@tauri-apps/plugin-dialog`：原生文件对话框（打开文件、选择目录）
- `@tauri-apps/plugin-process`：进程管理
- `tauri` Rust crate：后端框架，定义命令、管理状态、处理事件

### 2.2 React 18

**是什么**：React 是 Meta（Facebook）开发的用于构建用户界面的 JavaScript 库，核心思想是**组件化**和**声明式编程**。

**为什么用**：
- 组件化开发，代码复用性高
- 虚拟 DOM 提高性能
- 生态系统成熟，社区支持强大
- TypeScript 支持完善

### 2.3 TypeScript 5.3

**是什么**：TypeScript 是 JavaScript 的超集，添加了**静态类型系统**。代码在运行前需要编译为 JavaScript。

**为什么用**：
- 类型检查能在编码阶段发现错误，而非运行时
- 代码提示更智能（IDE 可以根据类型提供精确的自动补全）
- 代码可读性更强，类型即文档

### 2.4 Vite 5

**是什么**：Vite 是新一代前端构建工具，由 Vue.js 作者尤雨溪开发。

**为什么用**：
- 开发模式下使用原生 ES Module，启动速度极快（秒级启动）
- 热更新（HMR）速度快
- 基于 esbuild 的构建速度远超 Webpack

### 2.5 Tailwind CSS 3.4

**是什么**：Tailwind CSS 是一个**原子化 CSS 框架**，提供大量预定义的工具类（utility classes），可以直接在 HTML/JSX 中组合使用。

**为什么用**：
- 无需编写独立的 CSS 文件，样式直接写在元素上
- 设计系统一致
- 生产构建时自动移除未使用的 CSS，体积小

### 2.6 @dnd-kit

**是什么**：@dnd-kit 是 React 的拖拽库，提供可访问的拖放功能。

**本项目使用**：
- `@dnd-kit/core`：核心拖拽逻辑
- `@dnd-kit/sortable`：排序功能
- `@dnd-kit/utilities`：工具函数（如 CSS 变换）

### 2.7 Lucide React

**是什么**：Lucide 是一个开源图标库，提供 1000+ 个 SVG 图标的 React 组件版本。

**使用方式**：`import { Play, Square, Trash2 } from "lucide-react"`，然后在 JSX 中以 `<Play />` 方式使用。

### 2.8 Rust（后端语言）

**是什么**：Rust 是一门系统编程语言，以内存安全和高性能著称。

**为什么用**：
- Tauri 框架要求后端使用 Rust
- 内存安全（无垃圾回收器，通过所有权系统管理内存）
- 性能接近 C/C++
- 并发安全（编译器保证无数据竞争）

### 2.9 serde（Rust 序列化库）

**是什么**：serde 是 Rust 生态中最流行的序列化/反序列化框架。

**用途**：将 Rust 结构体与 JSON 之间相互转换，用于配置文件的读写和前后端数据传输。

### 4.1 package.json

```json
{
  "name": "service-deck",
  "version": "1.0.0",
  "description": "服务管理工具 - 管理和监控本地服务",
  "type": "module",
  ...
}
```

**逐字段解析**：

- `name`：项目名称，npm 包名
- `version`：遵循语义化版本（SemVer），格式为 `主版本.次版本.修订版本`
- `description`：项目描述
- `"type": "module"`：声明项目使用 ES Module 模块系统（而非 CommonJS），允许使用 `import/export` 语法

**scripts 脚本**：

```json
"scripts": {
  "dev": "tauri dev",           // 启动开发模式（同时启动前端和后端）
  "build": "tauri build",       // 构建生产版本
  "dev:renderer": "vite",       // 仅启动前端开发服务器
  "build:renderer": "vite build", // 仅构建前端
  "typecheck": "tsc --noEmit"   // 类型检查（不生成文件）
}
```

- `tauri dev`：Tauri CLI 命令，会同时启动 Vite 前端开发服务器和 Rust 后端编译，并打开桌面窗口
- `tauri build`：构建最终的可执行文件（.exe/.app）
- `vite`：仅启动前端开发服务器（http://localhost:1420）
- `tsc --noEmit`：运行 TypeScript 编译器检查类型错误，但不输出编译文件

**dependencies 运行时依赖**：

```json
"dependencies": {
```

### 4.2 vite.config.ts

```typescript
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import path from "path";

export default defineConfig({
  plugins: [react()],              // 使用 React 插件（支持 JSX 转换、Fast Refresh）
  resolve: {
    alias: {
      "@": path.resolve(__dirname, "./src"), // 路径别名：@ 指向 src 目录
    },
  },
  clearScreen: false,              // 不清除终端屏幕（保留 Tauri 日志）
  server: {
    port: 1420,                    // 开发服务器端口
    strictPort: true,              // 端口被占用时直接报错，而非自动换端口
  },
  envPrefix: ["VITE_", "TAURI_"],  // 只暴露以这些前缀开头的环境变量给前端
  build: {
    target: ["es2021", "chrome100", "safari13"], // 编译目标：支持的浏览器版本
    minify: !process.env.TAURI_DEBUG ? "esbuild" : false, // 调试模式不压缩代码
    sourcemap: !!process.env.TAURI_DEBUG, // 调试模式生成 source map
  },
});
```

**逐行解析**：

1. `defineConfig`：Vite 提供的辅助函数，提供 TypeScript 类型提示
2. `react()`：Vite React 插件，处理 JSX 语法转换和热更新
3. `alias`：路径别名，允许用 `@/components/TitleBar` 代替 `../../components/TitleBar`
4. `clearScreen: false`：默认 Vite 启动时会清屏，设为 false 保留 Tauri 的日志输出
5. `strictPort: true`：固定端口 1420，因为 Tauri 配置文件中也指定了这个端口
6. `envPrefix`：只有以 `VITE_` 或 `TAURI_` 开头的环境变量才会暴露给前端代码（安全考虑）
7. `target`：指定编译输出兼容的最低浏览器版本
8. `minify`：生产构建时压缩代码，调试时不压缩便于调试
9. `sourcemap`：调试时生成源码映射文件，便于定位错误

```json
{
  "compilerOptions": {
    "target": "ES2021",           // 编译目标版本
    "useDefineForClassFields": true, // 使用标准的类字段定义
    "lib": ["ES2021", "DOM", "DOM.Iterable"], // 可用的类型库

    "noEmit": true,               // 不输出编译文件（由 Vite 处理）
    "jsx": "react-jsx",           // JSX 转换模式
    "strict": true,               // 启用所有严格类型检查
```

**关键概念**：

- `"strict": true`：启用所有严格检查，包括 `noImplicitAny`（禁止隐式 any 类型）、`strictNullChecks`（严格的 null 检查）等

- `"moduleResolution": "bundler"`：使用打包工具的模块解析策略，支持路径别名
- `"isolatedModules": true`：确保每个文件可以单独编译（Vite 使用 esbuild，按文件独立处理）

### 4.4 tailwind.config.cjs

```javascript
/** @type {import('tailwindcss').Config} */
module.exports = {
  content: ["./index.html", "./src/**/*.{js,ts,jsx,tsx}"], // 扫描哪些文件中的类名
  darkMode: "class",              // 暗色模式通过 CSS 类名控制
  theme: {
    extend: {
      colors: {
        border: "hsl(var(--border))",        // 从 CSS 变量读取颜色值
        input: "hsl(var(--input))",
        ring: "hsl(var(--ring))",
        background: "hsl(var(--background))",
        foreground: "hsl(var(--foreground))",
        primary: {
          DEFAULT: "hsl(var(--primary))",
          foreground: "hsl(var(--primary-foreground))",
        },
        // ... 更多颜色定义
      },
      borderRadius: {
        lg: "var(--radius)",
        md: "calc(var(--radius) - 2px)",
        sm: "calc(var(--radius) - 4px)",
      },
    },
  },
  plugins: [],
};
```

**逐字段解析**：

1. `content`：Tailwind 会扫描这些文件，找出实际使用的 CSS 类，未使用的类不会打包（Tree Shaking）
2. `darkMode: "class"`：暗色模式通过在 HTML 元素上添加 `dark` 类来激活
3. `theme.extend`：扩展默认主题（而非替换），添加自定义颜色和圆角
4. 颜色使用 HSL 格式的 CSS 变量，如 `"hsl(var(--primary))"`，这样可以在 CSS 中动态切换主题

### 4.6 Cargo.toml

```toml
[package]
name = "service-deck"
version = "1.0.0"
description = "服务管理工具"
edition = "2021"                # Rust 版本（2021 版）

[lib]
name = "service_deck_lib"
crate-type = ["staticlib", "cdylib", "rlib"] # 输出库类型

[build-dependencies]
tauri-build = { version = "2", features = [] }

[dependencies]
serde_json = "1"                              # JSON 序列化/反序列化
serde = { version = "1", features = ["derive"] } # 序列化框架（启用 derive 宏）
tauri = { version = "2", features = ["tray-icon"] } # Tauri 框架（启用系统托盘）
tauri-plugin-dialog = "2"                     # 对话框插件
tauri-plugin-process = "2"                    # 进程管理插件
tauri-plugin-shell = "2"                      # Shell 插件
uuid = { version = "1", features = ["v4"] }   # UUID 生成库（v4 = 随机生成）
```

**逐行解析**：

- `edition = "2021"`：Rust 语言版本，不同版本有不同的语法特性
- `crate-type = ["staticlib", "cdylib", "rlib"]`：
  - `rlib`：Rust 原生库格式
  - `cdylib`：C 兼容的动态库
  - `staticlib`：静态库
  - Tauri 需要多种输出格式
- `features = ["derive"]`：serde 的 derive 功能允许通过 `#[derive(Serialize, Deserialize)]` 自动实现序列化
- `features = ["tray-icon"]`：启用 Tauri 的系统托盘功能
- `features = ["v4"]`：uuid 的 v4 版本（基于随机数生成 UUID）

### 5.1 React 基础概念

#### 5.1.1 JSX 语法

JSX 是 JavaScript XML 的缩写，允许在 JavaScript 中编写类似 HTML 的标记语言。

```tsx
// 这是 JSX
const element = <div className="text-white">Hello</div>;

// JSX 会被编译为 React.createElement 调用
const element = React.createElement("div", { className: "text-white" }, "Hello");
```

**JSX 与 HTML 的区别**：
- `class` 改为 `className`（因为 class 是 JavaScript 保留字）
- `for` 改为 `htmlFor`
- 属性名使用驼峰命名：`onclick` -> `onClick`，`tabindex` -> `tabIndex`
- 自闭合标签必须有斜杠：`<img />` 而非 `<img>`
- 表达式用花括号包裹：`{variable}`、`{condition ? "A" : "B"}`

**本项目中的 JSX 示例**（来自 `App.tsx`）：

```tsx
<button

>

</button>
```

解析：
- `onClick={() => setView("services")}`：点击时调用 `setView` 函数
- `className={...}`：使用模板字符串和三元运算符动态设置 CSS 类
- `${view === "services" ? "..." : "..."}`：根据当前视图状态切换样式

### 5.3 React Hooks 详解

#### 5.3.1 useState

`useState` 用于在函数组件中添加状态：

```typescript
const [services, setServices] = useState<Service[]>([]);
// 解构赋值：第一个元素是当前状态值，第二个是更新函数
// 初始值为 []（空数组）
```

#### 5.3.2 useEffect

`useEffect` 用于处理**副作用**（数据获取、订阅、定时器等）：

```typescript
// 基本用法：组件挂载后执行
useEffect(() => {
  loadData(); // 异步加载数据
}, []); // 空依赖数组 = 只在挂载时执行一次

// 带清理的用法
useEffect(() => {
  const timer = setInterval(async () => {
    const r = await invoke<string[]>("get_running_services");
    setRunningServices(r);
  }, 2000); // 每 2 秒轮询一次

  return () => clearInterval(timer); // 清理函数：组件卸载时清除定时器
}, [setRunningServices]); // 依赖数组：当 setRunningServices 变化时重新执行

// 错误提示自动消失
useEffect(() => {
  if (!globalError) return; // 没有错误就不设置定时器
  const timer = setTimeout(() => setGlobalError(null), 5000); // 5 秒后清除
  return () => clearTimeout(timer); // 清理：如果 globalError 变了，清除上一个定时器
}, [globalError]); // 依赖 globalError，每次错误变化都重新设置
```

**useEffect 的执行时机**：
1. 组件渲染到 DOM 后执行
2. 依赖数组中的值变化时重新执行
3. 返回的清理函数在下次执行前和组件卸载时调用

#### 5.3.3 useCallback

`useCallback` 用于**缓存函数**，避免每次渲染都创建新的函数引用：

```typescript
const loadServices = useCallback(async () => {
  try {
    const [s, r] = await Promise.all([
      invoke<Service[]>("get_services"),
      invoke<string[]>("get_running_services"),
    ]);
    setServices(s);
    setRunningServices(r);
  } catch (e) {
    console.error("加载服务失败:", e);
  }
}, []); // 空依赖 = 函数永远不会重新创建
```

**为什么需要 useCallback**：
- 如果不缓存，每次父组件渲染，子组件都会收到新的函数引用
- 新的函数引用会导致子组件重新渲染（即使数据没变）
- 作为其他 Hook 的依赖项时，新函数会导致 effect 重新执行

#### 5.3.4 useMemo

`useMemo` 用于**缓存计算结果**，只在依赖变化时重新计算：

```typescript
// 收藏优先排序
const sortedProjects = useMemo(() => {
  return [...projects].sort((a, b) => {
    if (a.favorite && !b.favorite) return -1; // a 收藏了，排前面
    if (!a.favorite && b.favorite) return 1;  // b 收藏了，排前面
    return a.sort_index - b.sort_index;       // 都没收藏，按 sort_index 排
  });
}, [projects]); // 只有 projects 变化时才重新排序

// 搜索过滤
const filteredServices = useMemo(() => {
  if (!serviceSearch.trim()) return sortedServices;
  const q = serviceSearch.trim().toLowerCase();
  return sortedServices.filter((s) => s.name.toLowerCase().includes(q));
}, [sortedServices, serviceSearch]); // 依赖排序后的列表和搜索关键词
```

**useMemo vs useCallback**：
- `useMemo` 缓存**值**（计算结果）
- `useCallback` 缓存**函数**
- `useCallback(fn, deps)` 等价于 `useMemo(() => fn, deps)`

#### 5.3.5 useRef

`useRef` 用于创建一个可变的引用对象，不会触发重新渲染：

```typescript
// 在 TitleBar 中缓存窗口引用
const appWindowRef = useRef(getCurrentWindow());
const appWindow = appWindowRef.current;
// appWindow 在整个组件生命周期中保持不变

// 在 LogViewerPanel 中引用 DOM 元素（用于自动滚动）
const logEndRef = useRef<HTMLDivElement>(null);
// ...
<div ref={logEndRef} /> // 将 DOM 元素绑定到 ref
logEndRef.current?.scrollIntoView({ behavior: "smooth" }); // 滚动到该元素

// 在 useConfirm 中存储 Promise 的 resolve 函数
const resolveRef = useRef<((value: boolean) => void) | null>(null);
```

**useRef 的特点**：
- `.current` 属性是可变的，修改它不会触发重新渲染
- 常用于：DOM 引用、定时器 ID、上一次的值、回调函数引用

#### 5.4.1 useServices.ts — 服务管理 Hook

```typescript
    const reordered = arrayMove(sortedProjects, oldIndex, newIndex);
```

#### 5.4.8 useConfirm.ts — 确认对话框 Hook

这是一个精巧的设计，将**命令式**的确认对话框封装为**Promise**：

```typescript
export function useConfirm() {
  const [options, setOptions] = useState<ConfirmOptions | null>(null);
  const resolveRef = useRef<((value: boolean) => void) | null>(null);

  // 组件卸载时自动 resolve，防止内存泄漏
  useEffect(() => {
    return () => {
      if (resolveRef.current) {
        resolveRef.current(false); // 未确认时默认返回 false
        resolveRef.current = null;
      }
    };
  }, []);

  // 返回 Promise 的 confirm 函数
  const confirm = useCallback((opts: ConfirmOptions): Promise<boolean> => {
    return new Promise((resolve) => {
      setOptions(opts);         // 显示对话框
      resolveRef.current = resolve; // 保存 resolve 函数
    });
  }, []);

  // 用户点击确认
  const handleConfirm = useCallback(() => {
    if (resolveRef.current) {
      resolveRef.current(true); // resolve Promise 为 true
      resolveRef.current = null;
    }
    setOptions(null); // 关闭对话框
  }, []);

  // 用户点击取消
  const handleCancel = useCallback(() => {
    if (resolveRef.current) {
      resolveRef.current(false); // resolve Promise 为 false
      resolveRef.current = null;
    }
    setOptions(null);
  }, []);

  return { options, confirm, handleConfirm, handleCancel };
}
```

#### 5.5.17 CommandTerminal.tsx — 命令终端

```tsx

  const [running, setRunning] = useState(false);

  useEffect(() => {
    const unlistenOutput = listen("command-output", (event) => {
      const payload = event.payload as { type: string; line: string };
      setOutput(prev => {
        const next = [...prev, { type: payload.type, text: payload.line }];
        return next.length > 5000 ? next.slice(next.length - 5000) : next; // 限制最大行数
      });
    });

    const unlistenFinished = listen("command-finished", (event) => {
      setRunning(false);
      // ...
    });

    return () => {
      unlistenOutput.then(fn => fn());
      unlistenFinished.then(fn => fn());
    };
  }, []);

  // 执行命令
  const executeCommand = useCallback(async (command: string) => {
    if (running || !command.trim()) return;
    setRunning(true);
    setOutput(prev => [...prev, { type: "command", text: `$ ${command}` }]);
    await invoke("execute_command", { command: command.trim(), workDir: servicePath });
  }, [running, servicePath]);
}
```

## 6. 后端代码详解

### 6.1 Rust 基础概念

#### 6.1.1 所有权（Ownership）

Rust 最独特的特性，编译器在编译时检查内存安全：

```rust
let s1 = String::from("hello");
let s2 = s1; // s1 的所有权移动到 s2，s1 不再有效
// println!("{}", s1); // 编译错误！s1 已经被移动

let s3 = s2.clone(); // 深拷贝，s2 和 s3 都有效
```

**在本项目中的体现**：

```rust
let service = services.get(&id).ok_or("服务不存在")?;
let updated = service.clone(); // 克隆一份，因为后面要释放锁
```

#### 6.1.2 借用（Borrowing）

不转移所有权，只是临时借用：

```rust
let s = String::from("hello");
let len = calculate_length(&s); // &s 是不可变借用
println!("{} 的长度是 {}", s, len); // s 仍然有效

fn calculate_length(s: &String) -> usize { // s 是 &String 类型（引用）
    s.len()
} // s 离开作用域，但因为只是借用，不会释放内存
```

**可变借用**：

```rust
let mut s = String::from("hello");
change(&mut s); // &mut s 是可变借用

fn change(s: &mut String) {
    s.push_str(", world");
}
```

**借用规则**：
- 同一时间只能有一个可变借用，或者多个不可变借用
- 借用不能超过值的生命周期

#### 6.1.3 生命周期（Lifetime）

编译器确保引用在其指向的数据有效期间不会被使用：

```rust
// 'a 是生命周期参数，表示返回的引用与两个输入引用中较短的那个生命周期一致
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

#### 6.1.4 错误处理

Rust 使用 `Result<T, E>` 类型处理可能失败的操作：

```rust
// Result 类型：Ok(成功值) 或 Err(错误值)
let content = fs::read_to_string(&path)
    .map_err(|e| format!("读取文件失败: {}", e))?;
// .map_err() 将错误类型转换为字符串
// ? 操作符：如果是 Err，直接返回错误；如果是 Ok，取出值继续

// 另一种方式
match serde_json::from_str(&json) {
    Ok(config) => config,
    Err(_) => AppConfig::default(), // 解析失败返回默认值
}
```

#### 6.1.5 trait（特征）

类似于其他语言的接口：

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Service {
    // ...
}
```

- `#[derive(...)]`：自动实现 trait
- `Debug`：支持 `{:?}` 格式化输出
- `Clone`：支持 `.clone()` 深拷贝
- `Serialize`：支持序列化为 JSON
- `Deserialize`：支持从 JSON 反序列化

```rust
#[tauri::command]
fn add_service(app: AppHandle, state: State<AppState>, name: String, command: String, ...) -> Result<Service, String> {
    // 1. 输入验证
    if name.trim().is_empty() {
        return Err("服务名称不能为空".to_string());
    }

    // 2. 获取锁
    let mut services = state.services.lock().unwrap();

    // 3. 检查名称唯一性
    if services.values().any(|s| s.name == name.trim()) {
        return Err("服务名称已存在".to_string());
    }

    // 4. 生成 UUID
    let id = uuid::Uuid::new_v4().to_string();

    // 5. 创建 Service 对象
    let service = Service { id, name, command, ... };

    // 6. 插入到 HashMap
    services.insert(id.clone(), service.clone());

    // 7. 释放锁
    drop(services);

    // 8. 保存到文件
    save_all(&app, &state)?;

    // 9. 返回新创建的服务
    Ok(service)
}
```

**update_service**：更新服务信息，并同步更新所有项目中的该服务

```rust
#[tauri::command]
fn update_service(...) -> Result<(), String> {
    let mut services = state.services.lock().unwrap();
    let service = services.get_mut(&id).ok_or("服务不存在")?;
    service.name = name;
    service.command = command;
    // ...

    // 同步更新所有项目中的该服务

    for project in projects.values_mut() {
        if let Some(svc) = project.services.iter_mut().find(|s| s.id == id) {

        }
    }

    drop(projects);

    Ok(())
}
```

**delete_service**：删除服务，同时停止进程并从项目中移除

```rust
#[tauri::command]
fn delete_service(app: AppHandle, state: State<AppState>, id: String) -> Result<(), String> {
    let mut services = state.services.lock().unwrap();
    let mut projects = state.projects.lock().unwrap();
    let mut processes = state.processes.lock().unwrap();

    let service = services.remove(&id).ok_or("服务不存在")?;

    // 停止该服务的进程
    if let Some(mut process) = processes.remove(&service.name) {
        let _ = process.kill();
        let _ = process.wait();
    }

    // 从所有项目中移除该服务
    for project in projects.values_mut() {
        project.services.retain(|s| s.id != id);
    }

    drop(services);
    drop(projects);
    drop(processes);
    save_all(&app, &state)?;
    Ok(())
}
```

#### 6.7.3 进程管理命令

```rust
#[tauri::command]
fn start_service(app: AppHandle, state: State<AppState>, service_name: String, command: Option<String>) -> Result<(), String> {
    let services = state.services.lock().unwrap();
    let mut processes = state.processes.lock().unwrap();

    // 查找服务
    let service = services.values().find(|s| s.name == service_name).ok_or("服务不存在")?;

    // 如果已运行，先强制杀死
    if let Some(mut process) = processes.remove(&service_name) {
        kill_process_tree(process.id());
        let _ = process.wait();
    }

    // 释放锁，避免阻塞前端轮询
    drop(processes);
    drop(services);

    // 启动进程（捕获实时日志）
    let child = spawn_with_realtime_log(&app, &service, &service_name, &state)?;

    // 保存进程句柄
    let mut processes = state.processes.lock().unwrap();
    processes.insert(service_name, child);
    Ok(())
}
```

**stop_service**：停止服务进程

```rust
#[tauri::command]
```

**get_running_services**：获取运行中的服务列表

```rust
#[tauri::command]
fn get_running_services(state: State<AppState>) -> Vec<String> {
    let mut processes = state.processes.lock().unwrap();
    let mut detected_pids = state.detected_pids.lock().unwrap();
    let mut running = HashSet::new();
    let mut exited = Vec::new();

    // 检查 processes 中的进程
    for (name, process) in processes.iter_mut() {
        match process.try_wait() {
            Ok(Some(_)) => {
                // 父进程已退出，检查 PID 是否还在
                if is_pid_alive(process.id()) {
                    running.insert(name.clone());
                } else {
                    exited.push(name.clone());
                }
            }
            Ok(None) => { running.insert(name.clone()); } // 还在运行
            Err(_) => { exited.push(name.clone()); }
        }
    }

    // 检查 detected_pids
    for (name, pid) in detected_pids.iter() {
        if is_pid_alive(*pid) {
            running.insert(name.clone());
        }
    }

    running.into_iter().collect()
}
```

```rust
fn read_file_tail(path: &PathBuf, n: usize) -> Result<String, String> {
    let metadata = fs::metadata(path)?;
    let file_size = metadata.len();

    // 小文件（< 1MB）：直接读取
    if file_size < 1024 * 1024 {
        let content = fs::read_to_string(path)?;
        let lines: Vec<&str> = content.lines().collect();
        let start = if lines.len() > n { lines.len() - n } else { 0 };
        return Ok(lines[start..].join("\n"));
    }

    // 大文件：从末尾向前按块读取
    let chunk_size: u64 = 8192;
    let mut pos = file_size;
    let mut tail_buf: Vec<u8> = Vec::new();
    let mut found_lines = 0;

    while pos > 0 && found_lines <= n {
        let read_size = chunk_size.min(pos);
        pos -= read_size;
        file.seek(SeekFrom::Start(pos))?;
        // 读取块并统计换行符
    }

    // 从缓冲区提取最后 n 行
}
```

```rust
            "code": status.code()

    });
```

### 7.1 invoke（前端调用后端）


**通信流程**：
1. 前端调用 `invoke("命令名", { 参数 })` 
2. Tauri 将参数序列化为 JSON
3. 通过 IPC（进程间通信）发送到 Rust 后端
4. 后端找到对应的 `#[tauri::command]` 函数
5. 将 JSON 参数反序列化为 Rust 类型
6. 执行函数，将返回值序列化为 JSON
7. 通过 IPC 返回给前端
8. 前端反序列化为 TypeScript 类型

### 7.2 event（后端推送前端）

```typescript
// 前端监听

  const payload = event.payload as { type: string; line: string };
```

**适用场景**：后端需要主动向前端推送数据（如实时日志输出、进程状态变化）。

### 7.3 Tauri IPC

IPC（Inter-Process Communication）是 Tauri 前端（WebView 进程）和后端（Rust 主进程）之间的通信通道。

- `invoke` 是**请求-响应**模式（前端发起，后端回复）
- `emit/listen` 是**发布-订阅**模式（后端随时推送，前端被动接收）

## 9. 关键设计模式

### 9.1 状态管理模式

**分层状态管理**：

```
App.tsx (全局状态)
├── useServices() — 服务列表 + 运行状态
├── useProjects() — 项目列表 + 运行状态
├── useLogs() — 日志内容
├── useServiceForm() — 服务表单状态
├── useProjectForm() — 项目表单状态
├── useBackup() — 备份状态
├── useConfirm() — 确认对话框状态
├── useDnD() — 拖拽状态
└── 本地 useState — 视图切换、搜索、错误提示
```

**设计原则**：
1. 自定义 Hook 封装相关状态和操作
2. 组件只负责渲染，状态逻辑在 Hook 中
3. 使用 `useCallback` 和 `useMemo` 避免不必要的重新计算
4. 全局错误提示集中在 App 组件管理

### 9.2 进程管理模式

**双通道进程管理**：

```
AppState
├── processes: HashMap<String, Child>      — 程序启动的进程（有完整的 Child 句柄）
└── detected_pids: HashMap<String, u32>    — 检测到的运行中进程（只有 PID）
```

- `processes`：程序通过 `spawn()` 启动的进程，持有 `Child` 句柄，可以控制 stdin/stdout/stderr
- `detected_pids`：启动时通过 `wmic` 和 `tasklist` 检测到的已在运行的进程，只有 PID

**进程生命周期**：
1. **启动**：`spawn_with_realtime_log()` 创建子进程，后台线程读取输出
2. **运行中**：`get_running_services()` 通过 `try_wait()` 和 `is_pid_alive()` 检查状态
3. **停止**：`kill_process_tree()` 递归杀死进程树（taskkill + wmic）
4. **退出后**：清理 processes/detected_pids 中的条目

### 9.3 日志系统

**双模式日志**：

1. **内存模式**（默认）：
   - 通过 `Stdio::piped()` 捕获 stdout
   - 后台线程逐行读取并存入 `log_buffers`
   - 前端每秒轮询获取
   - 日志界面关闭时保留 5 行，打开时保留 10000 行

2. **文件模式**（用户指定日志路径）：
   - 直接从日志文件读取
   - 使用 `read_file_tail` 高效读取末尾 N 行
   - 大文件使用分块读取避免 OOM

**日志界面状态通知**：
- 打开日志面板时调用 `set_log_viewer_active(true)`
- 后端根据此状态调整日志缓冲区大小
- 关闭时调用 `set_log_viewer_active(false)` 并清理缓冲区

### 9.4 配置持久化

**原子写入模式**：

```rust
fn save_config(app: &AppHandle, config: &AppConfig) -> Result<(), String> {
    let json = serde_json::to_string_pretty(config)?;
    let tmp_path = path.with_extension("json.tmp");
    fs::write(&tmp_path, &json)?;  // 先写临时文件
    fs::rename(&tmp_path, &path)?;  // 再重命名（原子操作）
    Ok(())
}
```

为什么用原子写入：如果写入过程中程序崩溃或断电，原文件不会损坏（因为还没被重命名）。

**配置文件位置**：与可执行文件同目录下的 `config.json`，便于携带和备份。

### 9.5 运行状态持久化

应用退出时将运行中的服务 PID 保存到配置文件，下次启动时检测这些 PID 是否仍在运行：

```rust
// 保存时
running_pids: HashMap<String, u32>,

// 启动时
for (service_name, pid) in &config.running_pids {
    if is_pid_alive(*pid) {
        detected_pids.insert(service_name.clone(), *pid);
    }
}
```

这样即使应用重启，也能正确显示哪些服务在运行。
